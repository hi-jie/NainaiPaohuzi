# 单机衡阳跑胡子功能规格

## 1. 产品范围

游戏以衡阳跑胡子为玩法范围，具体细则以奶奶平时打的口径为准。每桌一名真人玩家，固定两名 AI 陪玩。Android APK 内置网页、牌面和音频素材，安装后可离线完成开局、对局、结算和再来一局。电脑浏览器可预览同一份网页。

首页提供「开始游戏」「玩法设置」和当前累计积分。牌桌使用大字牌面、清楚的落地牌和易点按的动作按钮，真人决策时可慢慢选。结算页提供「再来一局」和「返回首页」。

## 2. 玩法设置

| 设置 | 行为 |
| --- | --- |
| 六胡抢 / 十胡卡 / 十五胡 | 三选一。每种玩法对应一份规则配置，按确认后的完整口径计算，玩法名称也显示在牌桌和结算页 |
| 一五十 | 可开关。开启后小字一五十计 3 胡息，大字壹伍拾计 6 胡息 |
| 放炮胡 | 可开关。开启可胡别人从手里打出的牌；关闭只可胡墩上摸出的牌，谁摸都可以。首发亮张暂归为发牌 |
| 强制动作 | 跑、偎、提自动执行，含起手提。胡牌优先于跑、碰、吃，真人的吃、碰需确认 |
| 音效 | 可开关。设置在重开应用后保留 |

开局时锁定本局规则快照。设置变更应用于下一局。各玩法的首次默认选项待确认。

## 3. 牌局与电脑玩家

1. 开局生成牌堆，洗牌、发牌并确定庄家。发牌数、起手特殊牌组和首局庄家按玩法配置处理。
2. 状态机推进到当前规则指定的摸牌、亮牌或出牌阶段，记录每张触发牌的来源和行动座位。
3. 每次出现响应机会，规则层为各座位生成合法动作，再按牌型、动作优先级和座次处理冲突。真人只看到当前可选动作，允许放弃时显示「过」。强制动作由状态机执行。
4. 吃牌需要选择组合时，展示完整合法方案，包括玩法要求的伴随牌组。碰、偎、提、跑更新手牌和落地牌，后续是否补牌、出牌或继续响应由规则决定。
5. 有人胡牌或达到流局条件后进入结算。结算完成后可直接开下一局，按规则决定下一局庄家。

状态机至少区分待开局、发牌、等待摸牌或亮牌、等待出牌、等待响应、结算、已结束。每次提交动作校验当前阶段、座位和合法性。动画由已提交的牌局事件驱动。连续点击和延迟到达的 AI 动作只在仍匹配当前决策时生效。

两名 AI 分别依据自己的手牌、可见桌面信息和合法动作决策。首版使用本地启发式逻辑，可先保留成组牌、优先打出价值较低的散牌。AI 与真人遵循同一套判定和强制动作规则，AI 决策可用固定种子复现，方便排查。

## 4. 胡牌、名堂与积分

- 胡牌判定综合手牌、落地牌、触发牌及其来源，按当前玩法检查合法拆分和起胡条件。
- 十胡卡有多种合法拆法时，取胡家最终积分最高的拆法。积分相同时取胡息较高的拆法。正好 10 胡按本玩法的 15 胡结算，实际胡息仍记 10。
- 结算列出胡牌者或流局、成牌组合、胡息、命中的名堂、倍率或加分明细、各座位本局积分变化，以及真人累计积分。
- 本地存档统一使用「积分」字段，承接原先金币计数的用途。首版累计积分从 0 开始，可累计为任意正常结算范围内的负整数、零或正整数。例如累计 -10、本局 -5，结算后显示 -15，「再来一局」仍可使用。
- 开局和续局只取决于牌局阶段。积分参与结果展示和存档，任何余额都能继续开局。
- 每局有唯一标识，结算时以同一次存档更新写入累计积分及已结算标识。重复触发同一局结算时，积分只变动一次。

## 5. 牌桌与动作表现

牌桌显示三座位、庄家标记、行动提示、剩余牌数、真人手牌和各家落地牌。落地牌按组显示，能区分吃、碰、偎、提、跑，暗牌和可见信息按规则呈现。

| 动作 | 画面反馈 |
| --- | --- |
| 摸牌 | 从牌堆移动到对应位置，按规则展示牌面或背面 |
| 出牌 | 从行动座位移到出牌区 |
| 吃、碰 | 高亮响应牌，牌组移入对应座位的落地区 |
| 偎、提、跑 | 突出新建或升级的牌组，按规则显示明暗 |
| 胡 | 高亮胡牌和获胜座位，随后进入结算 |

动画期间清楚提示当前动作，下一次可操作时恢复按钮。衡阳方言音效在摸牌和出牌时读牌面，在吃、碰、偎、提、跑、胡、过时播放相应录音。同一玩家从本局第二次跑起播放另一段跑牌录音。麻雀牌中对家摸入暗手的牌不报牌面。素材随 APK 打包，音效开关独立于背景音乐。

## 6. 本地存档

首版持久化累计积分和设置，使用带版本号的本地存档。应用更新时保持同一 WebView 资源来源和存档键，以便继续读取旧数据。存档读取失败时应给出提示，避免静默覆盖已有数据。

首版按「保存已结算积分和设置」规划。应用退到后台再回前台时保留当前页面里的牌局。进程被系统结束后，可从首页重新开局，未完成的牌局不计分。

## 7. 开发前需确认的衡阳玩法细则

| 项目 | 需要确认的口径 |
| --- | --- |
| 三套玩法 | 牌张组成、发牌与庄家规则、起胡条件，以及「抢」「卡」分别改变哪些动作或判定 |
| 一五十 | 可用的大小字组合、胡息数、对胡牌拆分和吃牌的影响 |
| 放炮与响应 | 自摸、他人摸出或亮出、他人打出的区分；各来源的可响应动作；多人可胡时的裁决 |
| 强制动作 | 偎、提、跑的触发条件，强制动作与胡牌的先后，过张限制、伴随吃牌和后续摸打顺序 |
| 胡牌和结算 | 牌组胡息表、名堂及叠加方式、计分换算、付款座位、流局积分与轮庄 |

每种玩法至少收集一局奶奶认可的样例，记录触发牌来源、响应选择、最终牌组和结算数字，用作规则测试用例。

## 8. 验收场景

- 飞行模式下启动 APK，真人与两名 AI 打完一局并继续开局。
- 三种玩法可切换，一五十和放炮开关会改变对应牌例的合法动作或判定结果。
- 在规则允许跑的指定牌例中自动执行跑；响应冲突、非法动作和重复点击均有可复现的测试用例。
- 用确认过的样例核对胡牌拆分、名堂和每家积分变化，重复提交结算只记一次。
- 累计积分降到负数后可以立即再开一局，重启应用后积分及设置仍能读取。
- 真机可辨认落地牌、轮次和可用动作；八类动作可看到反馈，静音及缺少录音时都能继续玩。
