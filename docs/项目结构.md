# 单机衡阳跑胡子项目结构

使用一个 Android 应用模块和一份原生 HTML、CSS、JavaScript 源码。网页的实际目录就是 Android 的 assets 目录，桌面预览和 APK 直接使用这份文件，省去复制和前端构建步骤。

```text
│               └── audio/hengyang/
└── tests/
    └── fixtures/
```

## 计划文件和职责

下表是后续实现的落点。网页路径相对于 `android/app/src/main/assets/www/`。

| 路径 | 职责 |
| --- | --- |
| `index.html`、`css/app.css`、`js/main.mjs` | 页面骨架、样式和启动入口，连接牌局、界面、存档和声音 |
| `js/rules/presets.mjs` | 保存六胡抢、十胡卡、十五胡的规则配置与开关 |
| `js/rules/cards.mjs`、`actions.mjs` | 牌的表示、牌组、合法动作、强制动作和响应优先级 |
| `js/rules/hu.mjs`、`scoring.mjs` | 胡牌拆分、胡息、名堂及三座位分数变动 |
| `js/game/deck.mjs`、`state-machine.mjs` | 牌堆和洗发牌、牌局状态推进、提交动作校验及事件输出 |
| `js/ai/player.mjs` | 从可见信息和合法动作中选择行动，供两个座位共用 |
| `js/ui/screens.mjs`、`table.mjs`、`animations.mjs` | 首页、设置、结算、手牌及落地牌渲染，以及动作动画 |
| `js/storage/save.mjs` | 存档格式、版本迁移、积分结算去重及读写 |
| `js/audio/player.mjs`、`media/audio/hengyang/` | 按动作映射并播放衡阳方言录音 |
| `media/cards/` | 后续需要的牌面素材，首版可先用 CSS 和文字呈现 |
| `android/app/src/main/java/`、`res/`、`AndroidManifest.xml` | Java WebView Activity、应用图标和主题、应用清单 |
| `android/settings.gradle`、`build.gradle`、`app/build.gradle`、Gradle Wrapper | 壳工程配置、SDK 版本和 APK 构建 |
| `tests/*.test.mjs`、`tests/fixtures/` | Node.js 规则及状态机测试、可重放的衡阳牌例和预期结算 |

规则和状态机模块使用纯 JavaScript，浏览器、WebView 和 Node.js 可直接导入。界面提交玩家动作，状态机返回更新后的状态和事件，界面、动画及音效消费这些事件。积分存档由启动入口协调，结算页面只展示结果。

## 开发与验证路径

1. 用编辑器的本地 HTTP 预览打开 `assets/www/index.html`，先完成可操作的三座位牌桌。
2. 把确认过的衡阳规则写入配置和判定，用 Node.js 自带的测试运行器核对牌例、响应、结算和负分续局。
3. 创建 Java WebView 壳。通过 `WebViewAssetLoader` 以固定资源来源加载同一网页并启用 DOM Storage。音频和牌面从 APK 读取。
4. 补齐 Android SDK 后，用 Gradle Wrapper 构建 APK，经 ADB 安装到手机，验证离线运行、触屏操作和重启后的存档。
