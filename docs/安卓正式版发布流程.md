# 安卓正式版发布流程

正式发布依次更新版本、构建并校验签名 APK、在 GitHub 和 Gitee 发布、验证 Pages 和 App 内更新。以下命令从仓库根目录在同一个 PowerShell 会话中执行。

## 1. 更新版本并提交

编辑 [version.json](../android/app/version.json)。`versionCode` 每次发布都递增，`versionName` 使用三段数字。Gradle 读取这两个字段；Pages 部署只在设置页显示 `versionName`。

确认两个远端均已配置。本机没有 Gitee 远端时执行 `git remote add gitee https://gitee.com/hi-jie/nainai-paohuzi.git`，并通过 Git 凭据管理器配置 Gitee 写入凭据。

```powershell
if ((git branch --show-current).Trim() -ne 'main') { throw 'Switch to main before releasing.' }
$releaseInfo = Get-Content android/app/version.json -Raw | ConvertFrom-Json
$releaseTag = "v$($releaseInfo.versionName)"
$apkName = "NainaiPaohuzi-$($releaseInfo.versionName)-release.apk"
node --test
if ($LASTEXITCODE -ne 0) { throw 'Tests failed.' }
git add -- android/app/version.json
git commit -m "Bump Android to $($releaseInfo.versionName)" -- android/app/version.json
if ($LASTEXITCODE -ne 0) { throw 'Version commit failed.' }
if (git status --porcelain) { throw 'Commit the remaining release changes before building.' }
$releaseCommit = (git rev-parse HEAD).Trim()
```

## 2. 构建正式签名 APK

使用 JDK 17 和 Android SDK Platform 35。设置 `ANDROID_HOME` 指向 SDK，或在 `android/local.properties` 填写 `sdk.dir`。APK 的包名是 `io.github.hijie.nainaipaohuzi`。后续发布沿用这个包名和「衡阳跑胡子」正式签名，用户才能覆盖安装并保留本地数据。

本机签名文件位于 `%LOCALAPPDATA%\NainaiPaohuzi\signing\`，密钥库为 `nainaipaohuzi-release.p12`，别名为 `nainaipaohuzi-release`。下面的命令用当前 Windows 账号解密密码，临时传给 Gradle。换电脑时，从备份恢复同一密钥库，并用 `Read-Host -AsSecureString` 在本机输入备份密码替代解密步骤。密钥库和密码单独备份，留在仓库外。

```powershell
$signingDir = Join-Path $env:LOCALAPPDATA 'NainaiPaohuzi/signing'
$encryptedPassword = Get-Content (Join-Path $signingDir 'release-password.dpapi') -Raw
$securePassword = ConvertTo-SecureString $encryptedPassword.Trim()

Push-Location android
try {
    $env:PAOHUZI_SIGNING_STORE_FILE = Join-Path $signingDir 'nainaipaohuzi-release.p12'
    $env:PAOHUZI_SIGNING_KEY_ALIAS = 'nainaipaohuzi-release'
    $env:PAOHUZI_SIGNING_STORE_PASSWORD = [System.Net.NetworkCredential]::new('', $securePassword).Password
    $env:PAOHUZI_SIGNING_KEY_PASSWORD = $env:PAOHUZI_SIGNING_STORE_PASSWORD

    .\gradlew.bat :app:assembleRelease --no-daemon --console=plain
    if ($LASTEXITCODE -ne 0) { throw 'Release build failed.' }
} finally {
    Remove-Item Env:PAOHUZI_SIGNING_STORE_FILE,Env:PAOHUZI_SIGNING_KEY_ALIAS,Env:PAOHUZI_SIGNING_STORE_PASSWORD,Env:PAOHUZI_SIGNING_KEY_PASSWORD -ErrorAction SilentlyContinue
    Pop-Location
}
```

复制构建产物，文件名为 `NainaiPaohuzi-<版本>-release.apk`。以下命令通过 `ANDROID_HOME` 找到 Android SDK Build Tools 34.0.0，校验 APK 签名并显示包名和版本。

```powershell
$apkDir = 'android/app/build/outputs/apk/release'
$apkFile = Join-Path $apkDir $apkName
Copy-Item -LiteralPath (Join-Path $apkDir 'app-release.apk') -Destination $apkFile
$buildTools = Join-Path $env:ANDROID_HOME 'build-tools/34.0.0'
& "$buildTools/apksigner.bat" verify --print-certs $apkFile
if ($LASTEXITCODE -ne 0) { throw 'APK signature verification failed.' }
& "$buildTools/aapt.exe" dump badging $apkFile | Select-String '^package:|^sdkVersion:|^application-debuggable'
Get-FileHash -Algorithm SHA256 -LiteralPath $apkFile
```

确认 `versionName`、`versionCode` 与 `version.json` 一致，输出中没有 `application-debuggable`，并记录 APK 的 SHA-256。当前正式证书的 SHA-256 指纹为 `d716265ad08deb67313c251f271c16667ded9f8c73aa8dccdf80a8c2bcc03e9a`。

## 3. 同步代码与发布双仓库 Release

把正式包对应的提交和同名标签推送到两个仓库。切换更新源的首个版本可先发布 Gitee，验证匿名下载后再推 GitHub，让旧 Pages 更新源在迁移包可用后下线。

```powershell
git tag $releaseTag $releaseCommit
if ($LASTEXITCODE -ne 0) { throw 'Tag creation failed.' }
git push --atomic gitee main "refs/tags/$releaseTag"
if ($LASTEXITCODE -ne 0) { throw 'Gitee push failed.' }
git push --atomic origin main "refs/tags/$releaseTag"
if ($LASTEXITCODE -ne 0) { throw 'GitHub push failed.' }
git ls-remote --tags gitee "refs/tags/$releaseTag"
git ls-remote --tags origin "refs/tags/$releaseTag"
```

- [GitHub Releases](https://github.com/hi-jie/NainaiPaohuzi/releases) 选择该标签，填写更新说明并上传 `$apkFile`，标为 **Latest release**。
- [Gitee Releases](https://gitee.com/hi-jie/nainai-paohuzi/releases) 使用同一个标签、更新说明和 APK，发布为正式版。说明末尾单独放一行 `versionCode: <整数>`（不加反引号），例如 `versionCode: 7`。App 从标签读显示版本，从这一行读内部版本号，通过 Gitee API 获取并下载同名附件。 [Gitee 发行版说明](https://help.gitee.com/repository/release/create)

## 4. 验证公开更新接口与网页部署

用以下命令匿名访问 App 使用的接口，并核对下载文件的 SHA-256。发布步骤使用的凭据不参与检查。

```powershell
$api = 'https://gitee.com/api/v5/repos/hi-jie/nainai-paohuzi/releases'
$online = Invoke-RestMethod "$api/latest"
if ($online.tag_name -ne $releaseTag -or $online.prerelease -or
    $online.body -notmatch "(?m)^versionCode: $($releaseInfo.versionCode)\r?$") { throw 'Gitee release metadata does not match.' }
$attachmentsUrl = "$api/$($online.id)/attach_files"
$files = Invoke-RestMethod $attachmentsUrl
$attachments = @($files | Where-Object name -eq $apkName)
if (@($attachments).Count -ne 1) { throw 'Expected exactly one matching Gitee APK.' }
$downloadedApk = Join-Path $env:TEMP "paohuzi-gitee-$apkName"
curl.exe --fail --location --output $downloadedApk "$attachmentsUrl/$($attachments.id)/download"
if ($LASTEXITCODE -ne 0) { throw 'Gitee APK download failed.' }
if ((Get-FileHash -LiteralPath $downloadedApk).Hash -ne
    (Get-FileHash -LiteralPath $apkFile).Hash) { throw 'Gitee APK SHA-256 does not match.' }
```

在 [GitHub Actions](https://github.com/hi-jie/NainaiPaohuzi/actions/workflows/pages.yml) 确认 `$releaseCommit` 对应的 Pages 部署成功。打开 [网页试玩](https://hi-jie.github.io/NainaiPaohuzi/)，在设置页核对版本。首次迁移后，旧 `update.json` 和 Pages APK 地址应返回 404。

## 5. 在手机上验证升级

从使用 Pages 更新源的旧版本迁移时，请先从任一 Release 下载迁移版 APK 并覆盖安装。后续用已接入 Gitee 更新的旧正式版测试。在「设置 → 检查更新」确认只在点击后查询，看到新版本后先点取消，再检查并确认下载。确认进度条替换检查按钮，下载完成后出现「安装」。需要允许此来源安装时，按系统提示授权，再完成系统安装。升级后查看设置页的版本号，并核对积分和存档。最后再次检查更新，应显示「已是最新版本」。

只做本地同版本试包时，可沿用当前版本号和正式签名。App 以 `versionCode` 判断有没有新版本，同版本试包应通过手动安装验证界面。
